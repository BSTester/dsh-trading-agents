# 量化交易快路径（Fast Path）

**这是快路径：不做多分析师、不做辩论、不写长研报。** 目标是在几秒~几十秒内
给出可执行的信号与参数。只有在用户**明确要求深度投研/完整研报**时，才改用
`trading-agents` 技能走 12 角色流程。

## 何时用哪条路径（强规则）

| 用户诉求 | 走哪条 |
|---|---|
| "现在能不能买/卖"、"看下信号"、"短线怎么做"、"跑个回测"、"量化/系统化交易" | **本技能（快路径）** |
| "帮我深度分析一下"、"出一份研报"、"多角度评估"、"辩论一下多空" | `trading-agents`（12 角色流程） |
| 诉求模糊 | 默认快路径；先给信号与参数，再问是否需要完整研报 |

绝不要为了回答"能不能买"而启动 12 角色流程——那是分钟级、十几次模型调用的成本。

## 快路径步骤

1. **取信号**：调用 `quant_signal(ticker, strategy)`。
   默认 `strategy=rsi`；需要趋势跟随用 `ma_cross`。
   返回 `signal`（BUY/SELL/HOLD）、`price`、`atr`、`date`。
2. **判读**：
   - `HOLD` → 直接回答"当前无信号，建议等待"，不编造理由、不启动深入研究；
   - `BUY`/`SELL` → 进入第 3 步。
3. **风控参数**（本地计算，不需要模型权衡）：
   - 止损：`入场价 − 2×ATR`；
   - 单笔风险：账户权益的 1%；
   - 仓位：`floor(风险预算 / (入场价 − 止损) / 100) × 100`（A股整手）；
   - 最大持仓数 5。
4. **（可选）回测确认**：用户要求验证策略时调用 `quant_backtest`，
   报告收益/年化/夏普/最大回撤/胜率与交易次数。**不要**因为回测好看就加大仓位。
5. **下单（仅当用户明确要求）**：
   - 先读 `trading_status` 确认账户模式（sim/live）与是否有进行中的调用；
   - sim 模式：展示订单摘要 → 用户确认 → 调 `sim_trade_*`；
   - live 模式：展示订单摘要 → 用户逐字确认 → 调 `trading_*`，并遵守 Harness 的
     审批弹窗（策略强制，不可绕过）；
   - 账户模式必须与工具前缀匹配，策略会拒绝跨模式调用。
6. **记录**：`quant_signal`/`quant_backtest` 的结果会写入工作台预览，
   无需额外写长文；用户要看历史时用 `trading_status` 或在 Harness 里查询。

## 硬约束

- 快路径**不产出投资建议性长文**，只给信号、参数、一句话依据与免责声明。
- 数据必须来自工具返回（富途行情/新浪日线），并标注数据日期；不得编造。
- 本地台账/预览**不是**券商持仓与成交；账户状态一律用富途查询工具。
- 实盘操作一律经 Harness 审批；不要在 shell 或 HTTP 里绕过工具策略直接下单。
- 未取到数据或工具失败 → 明确说明失败原因，不要用估算值替代。
