# TradingAgents 投研流水线

模拟一家投资机构的完整决策链：先并行收集四类数据，再让多空双方辩论、经理裁决，交易员给出提案，三方风控辩论后由组合经理终审。

## 阶段 0 · 准备

1. 确定标的代码与市场（如 `00700.HK`、`AAPL.US`）。用户没给代码时先问，不要猜。
2. 确定分析日期（默认今天）与持有视角（短线/中线，默认中线）。
3. **富途授权检查（首次运行必须做）**：检查工具列表里是否有 `mcp__futu__` 前缀的工具。
   - 有 → 直接使用，数据注明来源与时间。
   - 没有 → 说明当前未接入富途数据，询问用户选择：
     a. **去授权**——告诉用户按仓库 README「获取富途 token」完成 OAuth 授权，
        设置 `FUTU_MCP_TOKEN` 环境变量后重启会话即可启用富途行情/交易工具；
     b. **继续降级分析**——用 web 搜索获取公开数据，并在报告中标注
        "数据源：公开网络，非实时行情"。
   - 不要在未提示的情况下默默降级；也不要因为缺工具而拒绝分析。
4. 读取 `.tradingagents/memory.md`（若存在），摘出该标的的历史决策与教训，供后续阶段注入。

## 阶段 1 · 四位分析师（并行子代理）

四位分析师**用 subagent 工具并行派出**（一条消息里同时发起 4 个 subagent 调用），每个子代理的 prompt 包含：①角色与报告要求（见下表）；②当前标的、日期、持有视角；③数据获取指令——优先 `mcp__futu__*` 工具，不可用则用 web 搜索/抓取，禁止编造；④要求以"300 字以内报告 + 要点 Markdown 表格"返回。

| 角色 | 数据来源 | 报告内容 |
|---|---|---|
| 市场分析师 | `mcp__futu__quote_*`（K线/报价/盘口）；无 MCP 时用 web 搜索 | 趋势、动量、波动率、关键支撑/压力位 |
| 舆情分析师 | `mcp__futu__` 新闻/社区动态；无 MCP 时 web 搜索 | 近期新闻情绪、散户讨论热度与倾向 |
| 新闻分析师 | 新闻 + 宏观搜索 | 宏观与行业事件对标的的影响 |
| 基本面分析师 | `mcp__futu__` 财务/估值/股东；无 MCP 时 web 搜索 | 财务健康度、估值水平、核心风险 |

- 子代理不可用时（无 subagent 工具或派发失败），退回主会话内逐个完成四份报告。
- 收齐四份报告后，向用户简要展示各报告要点表格，再进入辩论阶段。
- 后续辩论/裁决阶段引用报告时引用要点，不要把全文重复贴出。

## 阶段 2 · 多空辩论（默认 2 轮）

- **Bull 研究员**：基于四份报告，主张买入逻辑，直接反驳 Bear 上一条论点。
- **Bear 研究员**：基于四份报告，主张风险逻辑，直接反驳 Bull 上一条论点。
- 每条发言 200 字以内，引用具体数据。轮次可由用户调整。

## 阶段 3 · 研究经理裁决

综合辩论，输出结构化评级（必须恰选其一）：`Buy / Overweight / Hold / Underweight / Sell`，附核心理由与战略动作建议。

## 阶段 4 · 交易员提案

基于裁决给出可执行提案：`Buy / Hold / Sell`、入场参考价、止损位、仓位建议（组合百分比）、持有周期。

## 阶段 5 · 三方风控辩论（各 1 条发言）

- **激进派**：为交易员提案辩护，强调上行空间与机会成本。
- **保守派**：攻击提案的风险敞口，给出更保守的替代方案。
- **中立派**：权衡双方，提出折中调整（如减半仓位、分批建仓）。

## 阶段 6 · 组合经理终审

输出最终决策，格式固定：

```markdown
## 📊 最终决策：<标的>（<日期>）

**评级**：Buy | Overweight | Hold | Underweight | Sell（恰选其一）
**操作**：<方向> <仓位> ＠ 参考价 <价格>，止损 <价格>
**期限**：<建议持有周期>

**核心论点**（≤5 条，每条一句话+数据）
**主要风险**（≤3 条）
**历史教训**：<来自 memory.md 的上期反思，首次分析标明"无历史记录">

> 本分析为 AI 研究输出，不构成投资建议。
```

## 阶段 7 · 记忆落盘（必须执行）

把最终评级与核心论点以 pending 条目追加写入 `.tradingagents/memory.md`：

```
[<日期> | <标的> | <评级> | pending]
DECISION: <一句话论点>
```

并在回复末尾提示用户：可以过几天回来执行"复盘 <标的>"，由你取真实涨跌幅生成反思、更新记忆。

## 复盘模式

用户说"复盘 <标的>"时：读 memory.md 中该标的 pending 条目 → 用 MCP/web 取决策日至今涨跌 → 为每条生成 2~3 句反思（方向对不对、论点哪些成立、下次怎么办）→ 更新条目为 `[日期 | 标的 | 评级 | +X% | 持有N天]` + REFLECTION。

## 交易执行（可选，默认模拟盘）

用户明确要求下单时：
1. 确认 `mcp__futu__` 交易工具可用；不可用则说明并停止。
2. 展示完整订单摘要（账户类型[默认模拟]、标的、方向、数量、价格、有效期）。
3. **必须**获得用户明确肯定回复后才可调用下单工具；模拟盘用 `sim_trade_*`，真实盘额外遵守工具返回的 `need_order_confirm` 二次确认流程。
4. 真实盘下单前，无论用户之前说过什么，都要再次逐字复述订单并要求确认。
