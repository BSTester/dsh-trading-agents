# TradingAgents 投研流水线

模拟一家投资机构的完整决策链，共 **12 个角色、6 个阶段**（对齐 TauricResearch/TradingAgents 官方图结构）：

- 阶段1 分析师 ×4（市场 / 社交舆情 / 新闻 / 基本面，官方 `selected_analysts` 默认即这四个，可按需增减）
- 阶段2 研究员辩论 ×2（Bull / Bear，默认 2 轮，即 `2 × max_debate_rounds` 条发言）
- 阶段3 研究经理 ×1（裁决，官方用深度思考模型）
- 阶段4 交易员 ×1（生成提案）
- 阶段5 风控辩论 ×3（激进 / 保守 / 中性轮转发言，`3 × max_risk_discuss_rounds` 条）
- 阶段6 组合经理 ×1（终审，官方用深度思考模型，注入历史决策反思）

分析师阶段每位分析师带工具循环（取数→写报告），辩论阶段辩手看得到完整辩论记录和对方最新发言。

## Harness 与工作台的职责

- **唯一指令入口是 Harness**。取数、子代理研究、复盘、下单与撤单都在当前对话中进行；不创建独立聊天、交易表单或绕过 MCP 的 HTTP/脚本下单路径。
- 完整安装后，先调用 `run_trading_analysis(ticker)` 取得研究记录 `id`。该工具仅启动记录，不调用私有 LLM、不替你取数或完成分析。保留 `id`，继续执行下面的完整流程。
- 完成终审后调用 `research_publish(run_id, ticker, rating, report, sources)`。`sources` 至少一项，每项含 `name`、`as_of`（数据时间）和 `reference`（URL 或 Harness 工具记录）。没有可靠数据时不得编造报告或用默认 Hold 掩盖失败。
- `trading_status` 返回工作台快照；`quant_signal`、`quant_backtest`、`quant_report` 的结果自动保存为量化预览，均不下单。本地模拟台账不是富途模拟账户。
- `research_cancel` 处理**被中断的会话留下的孤儿记录**：这种 run 会永远停在 `running`，
  面板「研究」页一直显示"进行中"。用户问起时按下面处理，**不要让他去点什么按钮**
  （工作台是只读展示，指令入口只有对话）：
  - 先 `research_cancel(action="list")` 把当前进行中的记录列出来给他看；
  - 确认要取消哪一条后 `research_cancel(action="cancel", run_id=...)`——
    只把状态改成 `cancelled` 并**保留记录**，不删数据、不影响已发布的研报；
  - 积压较多时用 `research_cancel(action="cancel_stale", older_than_minutes=120)` 批量处理；
  - 超过 2 小时仍 `running` 的，面板本就按派生状态显示为已中断（不改写磁盘数据），
    所以只有**不到 2 小时**的那些才需要人工确认。
- 工作台仅展示研报、最近的账户工具响应、量化预览和账户模式切换。动态来自 Harness 工具调用，不代表已经订阅券商成交推送。
- 文中的默认数据根目录为 `~/.dsh`；配置了 `DSH_HOME` 时以它为准。无插件时仍可执行基础 skill 流程，但不宣称有工作台或代码级账户守卫。

## 阶段 0 · 准备

1. 确定标的代码与市场（如 `00700.HK`、`AAPL.US`）。用户没给代码时先问，不要猜。
2. 确定分析日期（默认今天）与持有视角（短线/中线，默认中线）。
3. **富途通道检查（首次运行必须做）**：**必须真调一次工具，不能只看工具列表里有没有
   `mcp__futu__` 前缀。** 这一点很容易搞错，务必照做：
   - 工具在列表里 **不等于** 能用。富途 access_token 官方有效期只有 **2 小时**
     （`expires_in=7200`），而该 MCP 行的 Authorization 头是在**本会话组合挂载时求值一次**
     的固定字符串。token 过期后，服务端对所有工具返回 `internal error` 而**不是 401**，
     MCP 传输层看不出异常、不会重连，于是**工具继续列在列表里但每次调用都失败**。
   - 因此第一步就调一次最便宜的工具验证，例如 `mcp__futu__quote_trading_days`
     （参数 `{"market":"US","start":<7天前>,"end":<今天>}`）。
     - 返回数据 → 通道可用，继续；数据注明来源与时间。
     - 返回 `internal error` → **几乎可以断定是 token 过期**（不是"富途服务端故障"，
       历史上这个误判出现过）。执行 `--refresh` 续期，然后**新建会话**再试
       （见下方说明：已挂载的会话不会因为 touch 文件而重新读取组合）。
   - 完全没有 `mcp__futu__` 前缀的工具 → 可能未授权、MCP 启动失败或插件未加载。
     先区分原因，用户愿意授权时使用向导：
     a. 运行仓库自带脚本（跨平台 Python，Linux/macOS/Windows 通用）：
        `python "$HOME/.dsh/.agent-presets/dsh-trading-agents/scripts/futu_auth.py"`
        （Windows 路径：`%USERPROFILE%\.dsh\.agent-presets\dsh-trading-agents\scripts\futu_auth.py`）
        脚本会自动注册客户端、弹出富途授权页面、等待用户在浏览器确认、
        自动换取 token 存入 ~/.dsh/futu-token。默认只申请只读 scope；
        用户明确要交易功能时加 `--write` 参数。
     b. 把脚本打印的授权链接以可点击形式展示给用户，说明"请登录富途账号并点确认"。
     c. 脚本会顺带 touch 一次 preset 组合文件，但**实测 preset 目录没有任何 watcher**，
        组合是在会话挂载时读取的——所以 touch 只对**之后新建的会话**生效，
        不会让当前已挂载的会话重新求值。授权或续期后，请**新建会话**（仍选本模式）
        再使用富途工具；在旧会话里等多久都不会出现。
   - 授权方式只有这一种（OAuth，脚本全自动），没有其他授权兜底，也不需要。
   - **token 文件存在不能证明 token 有效**，工具在列表里也不能。过期一律表现为
     `internal error`。续期用：
     `python "$HOME/.dsh/.agent-presets/dsh-trading-agents/scripts/futu_auth.py" --refresh`
     续期后**新建会话**。preset 里带有 `futu-keepalive` 行，会按节奏自动续期
     （默认每 10 分钟检查、剩余不足 30 分钟时续期），因此正常情况下不需要手工续期；
     但它同样只能让**新会话**拿到新 token。
   - 用户不愿排障时继续公开数据降级，并在报告中标注数据源与时间。
   - **用户不想现在授权** → **继续降级分析**：用 web 搜索/AKShare/Yahoo 获取公开数据，
     并在报告中标注"数据源：公开网络，非实时行情"。
   - 不要在未提示的情况下默默降级；也不要因为缺工具而拒绝分析。
4. 读取 `.tradingagents/memory.md`（若存在），摘出该标的的历史决策与教训，供后续阶段注入。
5. **确定唯一账户（互斥开关，有富途工具时必做）**：运行
   `python "$HOME/.dsh/.agent-presets/dsh-trading-agents/scripts/trade_mode.py"` 读取当前账户模式。
   - 输出 `sim` → 本次只使用模拟盘工具（`sim_trade_*`），**绝不**触碰真实账户工具；
   - 输出 `live` → 本次只使用真实账户工具（`account_*` / `trading_*`），**绝不**触碰模拟盘工具。
   两种账户类型永不并存操作；切 live 必须由用户在工作台输入「确认实盘」，模型不得用
   脚本替代确认。切回 sim 可用 `quant_switch(mode="sim")`。然后按模式取当前持仓与可用资金，重点记录：是否已持有
   该标的及占比、成本价、账户集中度、剩余可用资金。查不到时在提案中注明"未考虑现有持仓"。
6. **交易频率检查（有富途工具时必做）**：按第 5 步确定的账户模式，取该标的近期订单与成交记录
   （live：`account_orders_history`/成交记录；sim：`sim_trade_history_order_list`），
   结合 memory.md 近期决策，记录：最近一次操作时间、近 30 天操作次数、有无高频进出。
   取不到时注明"未评估交易频率"，该信息供阶段 4/6 的频率约束使用。

## 阶段 1 · 四位分析师（并行子代理）

四位分析师**用 subagent 工具并行派出**（一条消息里同时发起 4 个 subagent 调用）。每个子代理 prompt = 下面该角色的官方提示词核心 + 运行时信息（标的、日期、持有视角）+ 数据获取指令（优先 `mcp__futu__*`，不可用则 web 搜索，禁止编造）+ 输出要求（详细报告 + 结尾附要点 Markdown 表格，标注数据来源与时间）。

四位分析师的官方提示词核心：
- **市场分析师**：为当前市况选最多 8 个互补的技术指标（趋势/MACD/RSI/布林/ATR/VWMA 类，不冗余），说明理由，基于 K 线与指标写细致趋势报告，观点具体可执行；
- **社交舆情分析师**：分析过去一周社交媒体讨论、公司新闻与公众情绪，看遍所有来源，写全面深入的报告并给出情绪走向及交易含义；
- **新闻分析师**：覆盖公司特定新闻与宏观经济，写"当前世界状态"的全面报告；
- **基本面分析师**：尽可能详尽地覆盖公司画像、财务报表、基本财务数据与财务历史，给出完整基本面图景。

**统一数据工具（首选）**：有 `fin_news` / `fin_sentiment` 工具时直接调用（多源自动路由与降级已内置于代码）：
- `fin_news(ticker, name, count, lang)` —— 富途快讯 → AKShare(A股) → Yahoo RSS(港美)
- `fin_sentiment(ticker, x_query, count)` —— X 情绪 + A股千股千评

**手动降级路径（工具不可用时，经 bash + trading-venv）**：
- A股新闻：`"$HOME/.dsh/trading-venv/bin/python" -c "import akshare as ak; print(ak.stock_news_em(symbol='600519').to_string())"`
- 千股千评：`... -c "import akshare as ak; print(ak.stock_comment_em().query('代码==\"600519\"').to_string())"`
- Yahoo RSS：web 抓取 `https://feeds.finance.yahoo.com/rss/2.0/headline?s=AAPL&region=US&lang=en-US`（港美通用）

**Reddit 渠道**：`fin_sentiment` 同时聚合 Reddit 讨论（与 X 共用专属浏览器登录态）。首次使用需登录一次：
`"$HOME/.dsh/trading-venv/bin/python" "$HOME/.dsh/.agent-presets/dsh-trading-agents/plugins/fin-data/python/reddit_search.py" --login`

### 已知工具限制与规避（2026-09-13 全量体检结论）

对 91 个富途工具 + 8 个非富途工具逐个实调后的结论。**这些坑看起来都像"没数据"，
不会报错**，所以必须照下面的规避方式做，否则会静默拿到空结果：

| 场景 | 不要用 | 改用 | 证据 |
|---|---|---|---|
| 取新闻 | `quote_news_search` | **`fin_news`** | 该工具三次不同参数（中文名/代码/英文+lang）均返回 `ret_code:0, data:[]`；而 `fin_news` 走富途源 `sources_status.futu="ok"` 能正常返回 |
| 取机构评级 | `quote_research_rating_summary` | **`quote_research_analyst_consensus`** | 前者对 `HK.00700` 返回 `pagination.total=0`；后者同一标的返回 43 位分析师、目标均价 663.69 |
| 改单 | 反复重试 `sim_trade_modify_order` | **撤单 + 重新下单** | 该接口间歇性 `ret_code:-5 backend business error`（同一天有成功也有失败，与价格是否离谱无关）；失败时价格与数量均未生效 |
| 查历史订单 | `account_orders_history` **不传时间范围** | **必须传 `start`/`end`** | 不传时静默返回纯文本 `no data`（不报错、不提示），极易误判成"无历史订单"；补上时间范围后正常返回 |

**A 股实时行情不可用（权限问题，不是故障）**：`order_book` / `rt_data` / `rt_ticker` /
`stock_quote` / `market_snapshot` 对 A 股统一返回
`-9 realtime quote permission required`（日股同理）。分析 A 股时**不要依赖实时报价/盘口/逐笔**，
改用实测可用的路径：`history_kline`（日线/分钟 K 线）、`capital_flow`（分钟级资金流）、
`stock_screen`、`market_state`。港股与美股有实时权限（港股 LV2 十档、美股 LV2），可正常使用。
> 工作台的 A 股标的卡已按此降级：显示最近日线收盘并在 `note` 字段说明"实时快照不可用"。

**上下文炸弹（无分页、单次返回极大）**：`quote_financials_earnings_price_history`
（实测约 **336KB**）、`quote_financials_earnings_price_move`、`quote_corporate_actions_rehab`。
不要随手调用；确有需要时先确认输出规模。

**易错字段名**：`quote_combo_option_quote` 的腿字段是 `legs` 与 `quantity`（不是
`leg_list`/`qty`，错误分两级才暴露）；`quote_option_screen` 必须传 `field_filter`，
否则只返回 4 个默认字段其余全 `null`；`quote_company_executive_background` 用
`leader_name`（如 `马化腾`）而非 `display_leader_name`。

**不确定项（勿依赖）**：`quote_ipo_list_sg`（新加坡 IPO 列表恒为空）、
`quote_referencefuture_list`（关联期货为空，疑似入参格式问题，未定论）。

**渠道优先级**：凡富途 MCP 能提供的数据（行情/K线/盘口/公司资料/估值/财报/资金流/股东/分红/新闻/社区/板块）
一律优先走富途；AKShare/Yahoo/公开快讯为备用；X 为必取情绪渠道，Reddit 为补充。

**X 情绪说明**：`fin_sentiment` 内置 X 渠道（不可达自动跳过，无需处理）。首次使用 X 需一次性登录：
`"$HOME/.dsh/trading-venv/bin/python" "$HOME/.dsh/.agent-presets/dsh-trading-agents/plugins/fin-data/python/x_search.py" --login`
（登录态持久保存在 ~/.dsh/x-profile；搜索词用英文，可组合 `$代码`）。X 用途：情绪倾向 + 财报/异动/行业事件的第一手讨论，辅助交易员与风控判断。

- 子代理不可用时（无 subagent 工具或派发失败），退回主会话内逐个完成四份报告。
- 收齐四份报告后，向用户简要展示各报告要点表格，再进入辩论阶段。
- 后续辩论/裁决阶段引用报告时引用要点，不要把全文重复贴出。

## 阶段 2 · 多空辩论（默认 2 轮）

辩手可看到：四份分析师报告全文 + 完整辩论记录 history + 对方最新一条发言。发言直接与对方观点交锋，而非罗列数据。

- **Bull 研究员**（官方提示词核心）："你是看多分析师，为投资该股票构建强有力的、基于证据的做多论据。聚焦：增长潜力（市场机会、营收预期、可扩展性）、竞争优势（独特产品、品牌、市场地位）、积极指标（财务健康、行业趋势、近期利好）、以及对熊方论点的逐条反驳。以对话式风格 engage，展示多方立场为何更有说服力。"
- **Bear 研究员**（官方提示词核心）："你是看空分析师，提出反对投资该股票的充分论据。聚焦：风险与挑战（市场饱和、财务不稳定、宏观威胁）、竞争劣势（定位走弱、创新下滑、竞争威胁）、负面指标（用财务数据、市场趋势、近期利空做证据）、以及对牛方论点的批判性分析。直接 engage 对方最新发言，展示做空/回避立场的依据。"

每条发言 200 字以内，引用具体数据。轮次可由用户调整。

## 阶段 3 · 研究经理裁决

官方提示词核心："你是研究经理兼辩论主持人，批判性地评估本轮辩论，为交易员交付清晰可执行的投资计划。评级必须恰选其一：**Buy**（强烈看多，建仓/加仓）/ **Overweight**（建设性看好，逐步增加敞口）/ **Hold**（双方证据真正均衡时才可保留）/ **Underweight**（谨慎，减仓）/ **Sell**（强烈看空，退出/回避）。只要辩论中最强的论据支持明确立场，就必须给出明确评级，不要躲在 Hold 后面。输出：评级 + 辩论关键点总结（rationale）+ 给交易员的具体战略动作。"

## 阶段 4 · 交易员提案

官方提示词核心："你是交易员，基于分析师团队的综合分析做投资决策。以投资计划为基础，给出具体建议。输出结构：**操作**（买入/持有/卖出）、**理由**（2~4 句、锚定分析师报告与研究计划）、**入场参考价**、**止损价**、**仓位**（如'组合的 5%'）。**一律中文**。"

在官方结构之上，交易员提案前必须逐项过一遍**决策因素清单**（取得到的用数据说话，取不到的明确标注）：

**① 市场环境与时机**
- 大盘状态：标的所在市场指数近期趋势与位置（高位/低位/震荡），大盘逆风时降仓位；
- 事件日历：近期是否有财报、除净、指数调仓、重要宏观数据发布——事件窗口前建议等事件落地或降仓规避；
- 时段因素：临近假期/长周末流动性变差，注意提示。

**② 个股可交易性**
- 流动性：日均成交量是否支撑建议仓位（建议仓位 ≤ 近 20 日日均成交额的合理比例），买卖价差是否异常；
- 波动率匹配：用 ATR/近期振幅校验止损距离是否合理——波动大的标的仓位要相应缩小（同等的止损距离意味着更大的单笔风险敞口）。

**③ 风险回报结构**
- 每笔提案必须给出**风险回报比**（目标价距入场 vs 止损距入场，建议 ≥ 2:1，不足时说明为何仍值得做）；
- **最坏情况**：若止损位被击穿（考虑跳空可能按超出止损 50% 估算），亏损金额占组合的百分比，确认在可承受范围。

**④ 组合层面**
- 现有持仓（阶段0）：已持有/集中度/成本价，仓位按五种情形调整；
- **相关性暴露**：若组合已重仓同行业/高相关标的（如同时重仓多只中概科技），新仓位需按"组合视角"打折并在提案中说明；
- 可用资金约束：建议仓位不得超过可用购买力。

**⑤ 交易频率约束（依据阶段 0 第 6 步）**

- **近期已有同向操作**（如几天前刚加仓、本轮结论不变）→ 默认建议"持有不动"，避免为操作而操作；
- **短时间反复买卖**（近 30 天内对该标的有 ≥2 次反向操作，或持有不足一周拟卖出）→ 除非出现显著新信息，提案应默认 Hold，并明确点出过度交易的成本（手续费、滑点、踏空风险）；
- **确需反向操作** → 说明触发改变的新证据是什么、与上次操作的依据有何不同；
- **未取到频率数据** → 提案中注明"未评估交易频率"。

**⑥ 执行与成本**
- 交易成本：佣金+平台费用+（港股）印花税等对短线小仓位是否划算；
- 分批执行：大仓位建议拆分（如首仓 1/2 + 回踩确认加仓 1/2，或按价格网格），给出触发条件；
- 滑点提示：市价单在开盘/收盘时段滑点大，建议限价单与避开时段。

**⑦ 记忆与用户偏好**
- 历史教训（memory）：上期同类 setup 的反思必须回应；
- 用户风险偏好未明确时，默认稳健风格并在提案末尾注明"按稳健偏好给出，可要求更激进/保守版本"。

## 阶段 5 · 三方风控辩论（各 1 条发言）

三位都能看到：交易员决策、四份分析师报告、完整风控辩论记录、另外两派的最新发言，以及**当前持仓与集中度信息**。发言以对话式、交锋式进行，不搞特殊格式。仓位调整建议（尤其中立派的折中方案）必须落到"相对现有持仓怎么动"，而不是凭空给一个比例。

- **激进派**（官方提示词核心）："作为激进风控分析师，积极 champion 高风险高回报的机会。聚焦交易员决策的上行空间、增长潜力和创新收益，逐点反驳保守派与中立派，论证他们的谨慎会错过关键机会、假设过于保守，为什么高风险路径是最优路径。"
- **保守派**（官方提示词核心）："作为保守风控分析师，首要目标是保护资产、降低波动、确保稳健增长。批判性审视决策中的高风险元素，指出哪里会让公司承担不当风险，逐点反驳激进派与中立派，强调可持续性，论证低风险调整方案的长期优势。"
- **中立派**（官方提示词核心）："作为中立风控分析师，提供平衡视角。评估利弊、纳入更广泛的市场趋势与潜在经济变化，指出激进派过度乐观、保守派过度谨慎之处，主张适度、可持续的调整方案（如减半仓位、分批建仓），兼顾增长潜力与极端波动防护。"

## 阶段 6 · 组合经理终审

官方提示词核心："作为组合经理，综合风控辩论，交付最终交易决策。评级恰选其一（五档含义同阶段3）。上下文包含：研究经理的投资计划、交易员的提案、**过往决策与结果的教训**（memory 反思）。要果断，每个结论都要锚定分析师的具体证据。"

最终决策输出格式：

> **一律用中文表述结论。** 研报正文、评级、操作方向、状态都不得出现
> `Buy` / `Sell` / `Hold` / `BUY` / `open` 这类英文枚举——工作台会把它们
> 原样展示给用户。评级五档的中文对照见下表；`research_publish` 的
> `rating` 参数仍传英文码（接口枚举），但正文一律写中文。

| `rating` 传参 | 正文里写 |
|---|---|
| `Buy` | 买入 |
| `Overweight` | 增持 |
| `Hold` | 持有 |
| `Underweight` | 减持 |
| `Sell` | 卖出 |

同理，交易方向写"买入/卖出"（不是 BUY/SELL），持仓状态写"持仓中/已平仓"
（不是 open/closed），数据源状态写"正常/待配置/异常"（不是 ok/warn/fail）。

```markdown
## 📊 最终决策：<标的>（<日期>）

**评级**：买入 | 增持 | 持有 | 减持 | 卖出（恰选其一，中文；接口传参用 Buy/Overweight/Hold/Underweight/Sell）
**操作**：<新建仓/加仓/持有/减仓/清仓> <仓位> ＠ 参考价 <价格>，止损 <价格>
**相对现有持仓**：<已持有 X% → 动作后 Y%，依据：集中度/资金/成本价>
**交易频率**：<最近一次同标的操作时间与次数评估；触发变化的增量信息，或"无新信息，建议持有">
**风险回报比**：<目标价 vs 止损的比值，建议 ≥2:1，例外需说明；最坏情况亏损占组合 X%>
**期限**：<建议持有周期>

**核心论点**（≤5 条，每条一句话+数据）
**主要风险**（≤3 条）
**历史教训**：<来自 memory.md 的上期反思，首次分析标明"无历史记录">

> 本分析为 AI 研究输出，不构成投资建议。
```

## 阶段 7 · 记忆落盘（必须执行）

完整插件模式下先调用 `research_publish` 发布报告到工作台。`run_trading_analysis` 返回的
`previous_reports` 可补充历史上下文；它们是旧研报，不是经过结果检验的反思。
下述工作区记忆继续用于复盘，不将 pending 论点当作已验证教训。

把最终评级与核心论点以 pending 条目追加写入 `.tradingagents/memory.md`：

```
[<日期> | <sim|live>账户 | <标的> | <中文评级> | pending]
DECISION: <一句话论点>
POSITION: <该账户下的真实持仓与成本，无则省略>
```

**账户模式必须写进条目**（`sim` / `live`），并且**模拟盘与实盘永远不要混算**。
反面教材：2026-09-12 的记忆把模拟台账与实盘持仓合在一起统计，得出"19 仓"，
而实盘实际只有 5 仓；对真实仓位还按模拟台账的成本给出了"-35% 破位清仓"的结论，
而真实成本对应的其实是 +5% 浮盈。**同一个标的在两个账户里的成本、数量、
盈亏可以完全不同**，读到历史条目时先看它属于哪个账户。

写入前先读一遍该标的的既有条目：**只把同账户的条目当作本次决策的前提。**

并在回复末尾提示用户：可以过几天回来执行"复盘 <标的>"，由你取真实涨跌幅生成反思、更新记忆。
写入后检查文件：条目超过 20 条时，删除最旧的已复盘（非 pending）条目，防止无限增长。

### 实盘下单能力以**实际下单**为准

不要在规则里预设"某个地区/账户不能交易"。券商的能力限制会随账户、地区、
时间与监管变化，**唯一可靠的判据是实际发起一次委托并观察结果**。

- 历史条目里出现过的拒单信息（例如某次 FAILED 订单的 `last_err_msg`）
  只是**当时那一次**的观察，不是长期规则；
- 要确认实盘能不能下单，就在用户完成两次确认后**真下一个单**，以返回结果为准；
- 被拒时把原始错误原文记进记忆，并标明日期与账户，供后续判断是否仍然成立。

## 复盘模式

用户说"复盘 <标的>"时：读 memory.md 中该标的 pending 条目 → 用 MCP/web 取决策日至今涨跌 → 为每条生成 2~3 句反思（方向对不对、论点哪些成立、下次怎么办）→ 更新条目为 `[日期 | 标的 | 评级 | +X% | 持有N天]` + REFLECTION。

## 交易执行（可选，默认模拟盘）

用户明确要求下单时：
1. 确认 `mcp__futu__` 交易工具可用；不可用则说明并停止。
2. **读取账户模式开关**：`python "$HOME/.dsh/.agent-presets/dsh-trading-agents/scripts/trade_mode.py"`。
   - `sim` → 只用模拟盘工具（`sim_trade_input_order` 等），拒绝任何真实账户操作；
   - `live` → 只用真实账户写工具（`trading_input_order` / `trading_modify_order` / `trading_cancel_order`）与只读的 `account_*`，拒绝任何模拟盘操作；
   - 两个账户类型永不并存操作。切 live 由用户在工作台完成；切 sim 用 `quant_switch`。每次重新读取权威模式，不依赖对话里上一次模式。账户调用进行中不能切换。
3. 展示完整订单摘要（账户类型=当前模式、标的、方向、数量、价格、有效期）。
4. **必须**获得用户明确肯定回复后才可调用下单工具；模拟盘下单一次确认即可。
5. 真实盘下单前，无论用户之前说过什么，都要再次逐字复述订单并要求确认。

6. **实盘写操作还有一道必经的业务闸门，在工作台里，不在对话里。**

   调用 `trading_input_order` / `trading_modify_order` / `trading_cancel_order` 时，
   工具会**阻塞**并等待用户在工作台界面点「确认这笔操作」或「拒绝」，最长 2 分钟，
   超时按拒绝处理。这与 Harness 的权限审批无关：权限问的是"这个动作准不准做"，
   工作台问的是"这笔参数对不对"——后者是交易动作的固有环节，**任何权限档位下都必须确认**
   （full-access 也一样，不会被静默跳过）。

   因此调用前**必须先明确告诉用户去工作台确认**，例如：
   > 订单摘要：买入 TSLL 4 股 @ 9.30（实盘账户 281756480774050900）。
   > 请打开「交易工作台」确认这笔操作，我在等你点确认。

   否则用户在对话里看不到任何提示，只会觉得工具卡住了，然后等到超时被拒。

7. 被拒/超时后不要自动重试同一笔。工作台会给出拒绝原因；用户改主意时应由用户
   重新发起，而不是模型循环重试。收到超时、拒单或未知状态时**先查订单**
   （`account_orders_history` 必须传 start/end），确认到底有没有成交，再决定下一步。

8. 不要通过 shell、私有 HTTP 或其他工具绕过这道闸门，也不要试图代替用户作答——
   确认只能由用户在工作台点击产生。
