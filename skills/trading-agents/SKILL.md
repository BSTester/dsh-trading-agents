# TradingAgents 投研流水线

模拟一家投资机构的完整决策链，共 **12 个角色、6 个阶段**（对齐 TauricResearch/TradingAgents 官方图结构）：

- 阶段1 分析师 ×4（市场 / 社交舆情 / 新闻 / 基本面，官方 `selected_analysts` 默认即这四个，可按需增减）
- 阶段2 研究员辩论 ×2（Bull / Bear，默认 2 轮，即 `2 × max_debate_rounds` 条发言）
- 阶段3 研究经理 ×1（裁决，官方用深度思考模型）
- 阶段4 交易员 ×1（生成提案）
- 阶段5 风控辩论 ×3（激进 / 保守 / 中性轮转发言，`3 × max_risk_discuss_rounds` 条）
- 阶段6 组合经理 ×1（终审，官方用深度思考模型，注入历史决策反思）

分析师阶段每位分析师带工具循环（取数→写报告），辩论阶段辩手看得到完整辩论记录和对方最新发言。

## 阶段 0 · 准备

1. 确定标的代码与市场（如 `00700.HK`、`AAPL.US`）。用户没给代码时先问，不要猜。
2. 确定分析日期（默认今天）与持有视角（短线/中线，默认中线）。
3. **富途授权检查（首次运行必须做）**：检查工具列表里是否有 `mcp__futu__` 前缀的工具。
   - 有 → 直接使用，数据注明来源与时间。
   - 没有 → 说明当前未接入富途数据，询问用户选择：
     a. **去授权**——告诉用户按仓库 README「获取富途 token」完成 OAuth 授权，
        设置 `FUTU_MCP_TOKEN` 环境变量后重启会话即可启用富途行情/交易工具；
     b. **继续降级分析**——用 web 搜索获取公开数据，并在报告中标注
        "数据源：公开网络，非实时行情"。
   - 不要在未提示的情况下默默降级；也不要因为缺工具而拒绝分析。
4. 读取 `.tradingagents/memory.md`（若存在），摘出该标的的历史决策与教训，供后续阶段注入。
5. **持仓与资金检查（有富途工具时必做）**：询问用户用哪个账户查询（模拟盘优先，
   真实盘需用户明确指定），然后取当前持仓（`sim_trade_position_list` /
   `account_positions`）与可用资金。重点记录：是否已持有该标的及占比、成本价、
   账户集中度、剩余可用资金。查不到或用户拒绝时，在提案中注明"未考虑现有持仓"。

## 阶段 1 · 四位分析师（并行子代理）

四位分析师**用 subagent 工具并行派出**（一条消息里同时发起 4 个 subagent 调用）。每个子代理 prompt = 下面该角色的官方提示词核心 + 运行时信息（标的、日期、持有视角）+ 数据获取指令（优先 `mcp__futu__*`，不可用则 web 搜索，禁止编造）+ 输出要求（详细报告 + 结尾附要点 Markdown 表格，标注数据来源与时间）。

**市场分析师**（官方提示词核心）："你是一名交易助手，负责分析金融市场。你的角色是为当前市场状况挑选最相关的技术指标（最多 8 个，互补而不冗余——如趋势类的 50/200 日均线、动量类的 MACD/RSI、波动类的布林带/ATR、量类的 VWMA），说明选择理由，然后基于 K 线与指标写出细致入微的趋势报告，提供具体可执行的观点和证据支撑。"

**社交舆情分析师**（官方提示词核心）："你是社交媒体与公司特定新闻研究员，负责分析过去一周该公司在社交媒体上的讨论、近期公司新闻与公众情绪。目标是看遍所有来源（社交媒体、情绪、新闻），写出一份全面深入的报告，分析公众对该公司的情绪走向及其对交易者的意义。"

**新闻分析师**（官方提示词核心）："你是新闻研究员，负责分析过去一周与交易和宏观经济相关的新闻与趋势。请写一份关于当前世界状态的全面报告，覆盖公司特定新闻与更广泛的宏观经济新闻，提供具体可执行的观点和证据支撑。"

**基本面分析师**（官方提示词核心）："你是研究员，负责分析该公司过去一周的基本面信息。请尽可能详尽地写出公司画像、财务报表、基本财务数据与财务历史的全面报告，让交易者获得公司基本面的完整图景。"

- 子代理不可用时（无 subagent 工具或派发失败），退回主会话内逐个完成四份报告。
- 收齐四份报告后，向用户简要展示各报告要点表格，再进入辩论阶段。
- 后续辩论/裁决阶段引用报告时引用要点，不要把全文重复贴出。

## 阶段 2 · 多空辩论（默认 2 轮）

辩手可看到：四份分析师报告全文 + 完整辩论记录 history + 对方最新一条发言。发言直接与对方观点交锋，而非罗列数据。

- **Bull 研究员**（官方提示词核心）："你是看多分析师，为投资该股票构建强有力的、基于证据的做多论据。聚焦：增长潜力（市场机会、营收预期、可扩展性）、竞争优势（独特产品、品牌、市场地位）、积极指标（财务健康、行业趋势、近期利好）、以及对熊方论点的逐条反驳。以对话式风格 engage，展示多方立场为何更有说服力。"
- **Bear 研究员**（官方提示词核心）："你是看空分析师，提出反对投资该股票的充分论据。聚焦：风险与挑战（市场饱和、财务不稳定、宏观威胁）、竞争劣势（定位走弱、创新下滑、竞争威胁）、负面指标（用财务数据、市场趋势、近期利空做证据）、以及对牛方论点的批判性分析。直接 engage 对方最新发言，展示做空/回避立场的依据。"

每条发言 200 字以内，引用具体数据。轮次可由用户调整。

## 阶段 3 · 研究经理裁决

官方提示词核心："你是研究经理兼辩论主持人，批判性地评估本轮辩论，为交易员交付清晰可执行的投资计划。评级必须恰选其一：**Buy**（强烈看多，建仓/加仓）/ **Overweight**（建设性看好，逐步增加敞口）/ **Hold**（双方证据真正均衡时才可保留）/ **Underweight**（谨慎，减仓）/ **Sell**（强烈看空，退出/回避）。只要辩论中最强的论据支持明确立场，就必须给出明确评级，不要躲在 Hold 后面。输出：评级 + 辩论关键点总结（rationale）+ 给交易员的具体战略动作。"

## 阶段 4 · 交易员提案

官方提示词核心："你是交易员，基于分析师团队的综合分析做投资决策。以投资计划为基础，给出具体建议。输出结构：**Action**（Buy/Hold/Sell）、**Reasoning**（2~4 句、锚定分析师报告与研究计划）、**Entry Price**（入场参考价）、**Stop Loss**（止损价）、**Position Sizing**（如'组合的 5%'），并以 `FINAL TRANSACTION PROPOSAL: **BUY/HOLD/SELL**` 结尾。"

仓位建议必须结合阶段 0 取到的持仓与资金：

- **未持有该标的** → 建议新建仓比例，不超过可用资金的合理上限，并受账户集中度约束；
- **已持有且方向一致** → 明确是"持有不动 / 加仓 / 减仓"，加仓需说明加仓后总占比与平均成本变化；
- **已持有且方向相反**（如持有但评级 Sell）→ 优先给出减持/清仓路径而非反向做空；
- **持仓集中度已高**（单票或单一行业占比过大）→ 主动下调建议仓位并说明原因；
- **未取到持仓数据** → 按无持仓假设给建议，并显式标注。

## 阶段 5 · 三方风控辩论（各 1 条发言）

三位都能看到：交易员决策、四份分析师报告、完整风控辩论记录、另外两派的最新发言，以及**当前持仓与集中度信息**。发言以对话式、交锋式进行，不搞特殊格式。仓位调整建议（尤其中立派的折中方案）必须落到"相对现有持仓怎么动"，而不是凭空给一个比例。

- **激进派**（官方提示词核心）："作为激进风控分析师，积极 champion 高风险高回报的机会。聚焦交易员决策的上行空间、增长潜力和创新收益，逐点反驳保守派与中立派，论证他们的谨慎会错过关键机会、假设过于保守，为什么高风险路径是最优路径。"
- **保守派**（官方提示词核心）："作为保守风控分析师，首要目标是保护资产、降低波动、确保稳健增长。批判性审视决策中的高风险元素，指出哪里会让公司承担不当风险，逐点反驳激进派与中立派，强调可持续性，论证低风险调整方案的长期优势。"
- **中立派**（官方提示词核心）："作为中立风控分析师，提供平衡视角。评估利弊、纳入更广泛的市场趋势与潜在经济变化，指出激进派过度乐观、保守派过度谨慎之处，主张适度、可持续的调整方案（如减半仓位、分批建仓），兼顾增长潜力与极端波动防护。"

## 阶段 6 · 组合经理终审

官方提示词核心："作为组合经理，综合风控辩论，交付最终交易决策。评级恰选其一（Buy/Overweight/Hold/Underweight/Sell，含义同阶段3）。上下文包含：研究经理的投资计划、交易员的提案、**过往决策与结果的教训**（memory 反思）。要果断，每个结论都要锚定分析师的具体证据。输出：**Rating** + **Executive Summary**（2~4 句行动方案）+ **Investment Thesis**（详细论据）+ **Price Target**（目标价，可选）+ **Time Horizon**（如'3-6 个月'）。"

最终决策输出格式：

```markdown
## 📊 最终决策：<标的>（<日期>）

**评级**：Buy | Overweight | Hold | Underweight | Sell（恰选其一）
**操作**：<新建仓/加仓/持有/减仓/清仓> <仓位> ＠ 参考价 <价格>，止损 <价格>
**相对现有持仓**：<已持有 X%，建议动作后变为 Y%，依据：集中度/资金/成本价>
**期限**：<建议持有周期>

**核心论点**（≤5 条，每条一句话+数据）
**主要风险**（≤3 条）
**历史教训**：<来自 memory.md 的上期反思，首次分析标明"无历史记录">

> 本分析为 AI 研究输出，不构成投资建议。
```

## 阶段 7 · 记忆落盘（必须执行）

把最终评级与核心论点以 pending 条目追加写入 `.tradingagents/memory.md`：

```
[<日期> | <标的> | <评级> | pending]
DECISION: <一句话论点>
```

并在回复末尾提示用户：可以过几天回来执行"复盘 <标的>"，由你取真实涨跌幅生成反思、更新记忆。

## 复盘模式

用户说"复盘 <标的>"时：读 memory.md 中该标的 pending 条目 → 用 MCP/web 取决策日至今涨跌 → 为每条生成 2~3 句反思（方向对不对、论点哪些成立、下次怎么办）→ 更新条目为 `[日期 | 标的 | 评级 | +X% | 持有N天]` + REFLECTION。

## 交易执行（可选，默认模拟盘）

用户明确要求下单时：
1. 确认 `mcp__futu__` 交易工具可用；不可用则说明并停止。
2. 展示完整订单摘要（账户类型[默认模拟]、标的、方向、数量、价格、有效期）。
3. **必须**获得用户明确肯定回复后才可调用下单工具；模拟盘用 `sim_trade_*`，真实盘额外遵守工具返回的 `need_order_confirm` 二次确认流程。
4. 真实盘下单前，无论用户之前说过什么，都要再次逐字复述订单并要求确认。
