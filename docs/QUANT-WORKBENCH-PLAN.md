# 专业量化交易工作台方案（Quant Workbench Plan）

> 面向复审的设计文档：现状评估 → 机构级信息体系 → UI/图表方案 → 数据缺口 → 分阶段实施。

## 一、现状评估：当前工作台适合量化交易吗？

**结论：不适合做量化交易台，目前只是「结果与观察面板」。**

| 维度 | 现状 | 量化交易需要 |
|---|---|---|
| 布局 | 右下角浮层，三个平铺列表（研报/动态/预览）+ 模式切换 | 分类导航 + 主视图 + 行情/图表常驻 |
| 图表 | **零图表** | K线+指标、权益曲线、回撤、热力图、相关性矩阵 |
| 时间序列 | 无（`previews` 是单次结果快照） | 多周期序列、滚动窗口、事件对齐 |
| 分类 | 粗（3 类） | 行情/信号/组合/风险/执行/研究/事件 七大域 |
| 实时性 | 3 秒轮询 `snapshot` | 按需推送、订阅式更新、变化高亮 |
| 交互 | 折叠查看 JSON | 缩放/十字光标/叠加指标/区间选择/下钻 |
| 风险视图 | 无 | 敞口、集中度、相关性、VaR/回撤、杠杆 |

现有 `snapshot()` 返回 `{mode, generated_at, runs, reports, previews, activity, broker, in_flight, pending_observations, recording_error, notice}` —— 全部是**扁平列表**，没有任何序列型数据可画图。底层 91 个富途工具能提供图形所需原料，但工作台没有承载。

**可复用的地基**：Host store（原子写 + 模式隔离 + 观察记录）、RPC 白名单（`snapshot`/`switch-mode`）、策略强制（账户隔离 + 实盘审批）、量化脚本（信号/回测/台账）。这些继续用，改造集中在**数据模型 + UI**。

## 二、机构级量化交易需要的信息体系（七大域）

按顶尖投行/交易台的职责划分。每域标注「已有 / 需补」。

### 1. 市场数据（Market Data）
| 信息 | 用途 | 状态 |
|---|---|---|
| 实时快照（价/量/涨跌/振幅） | 定价基准 | ✅ `quote_stock_quote` |
| 多周期 K 线（1m/5m/15m/60m/D/W） | 信号与图形 | ⚠️ MCP K线工具报错，A股可走新浪日线 |
| 盘口深度（买卖五档/十档） | 冲击成本、流动性 | ✅ `quote_order_book` |
| 逐笔成交（tick） | 微观结构、量价背离 | ✅ `quote_rt_ticker`（轮询，非推送） |
| 分时序列 | 日内走势 | ✅ `quote_rt_data` |
| 资金流向（日内/历史） | 主力行为 | ✅ `quote_capital_flow(_history)` |
| 指数/板块/成分股 | 相对强弱、行业轮动 | ✅ `quote_plate_*`、`quote_valuation_*` |
| 市场状态/交易日历 | 交易时点、隔夜风险 | ✅ `quote_market_state`、`quote_trading_days` |

### 2. 因子与信号（Signals & Factors）
- 技术因子：均线族、MACD、RSI、布林、ATR、VWMA（现有 `quant_signal` 覆盖 2 个策略）
- 横截面因子：估值（`quote_valuation_detail`）、成长、质量、动量、波动、流动性
- 情绪因子：X（已接入）、富途社区（`quote_community_search`/`quote_stock_feed`）、千股千评（AKShare）
- 研报因子：分析师一致预期与目标价（`quote_research_analyst_consensus`）
- 微观结构因子：大单占比、买卖压力、经纪商队列（`quote_top_ten_brokers`）
- **需补**：因子库统一计算层、因子标准化/去极值、因子 IC/RankIC 检验

### 3. 组合与风险（Portfolio & Risk）
| 信息 | 状态 |
|---|---|
| 持仓、成本、浮动盈亏 | ✅ `account_positions` / `sim_trade_position_list` |
| 可用资金/购买力/保证金 | ✅ `account_funds`、`account_trading_info` |
| 单票/行业集中度 | ⚠️ 需计算层 |
| 相关性矩阵（持仓间、与指数） | ❌ 需补 |
| 波动率/回撤/VaR/ES | ❌ 需补（回测已有 max_drawdown） |
| 杠杆与敞口 | ⚠️ 部分（融资信息）|

### 4. 执行（Execution）
- 订单生命周期：活动/历史订单、成交明细（`account_orders_*`、`account_fills_*`）
- 最大可买卖（`account_trading_info`、`sim_trade_max_buy_sell`）
- **TCA（交易成本分析）**：滑点、成交价 vs 到达价、实现差价 —— ❌ 需补
- 委托执行质量：部分成交/废单率、排队位置 —— ⚠️ 部分

### 5. 研究（Research）
- 回测绩效：收益/年化/夏普/最大回撤/胜率 —— ✅ `quant_backtest`
- **需补**：参数敏感性、滚动前推（walk-forward）、样本外验证、策略归因、多标的组合回测、基准对比（超额/信息比率）

### 6. 事件与日历（Events）
- 财报/分红/拆股/回购（`quote_financials_*`、`quote_corporate_actions_*`）
- 经济数据日历（`quote_economic_calendar_search/hot`）
- 指数调仓、IPO（`quote_ipo_list_*`）
- **需补**：事件与持仓/信号的自动对齐（"T-1 财报，建议降仓"）

### 7. 账户、合规与审计（Account & Compliance）
- 账户模式（sim/live）互斥隔离 —— ✅ 已强制
- 交易授权与审批流 —— ✅ 策略强制 + Harness 审批
- 审计日志：谁在何时下了什么单、依据哪次信号 —— ⚠️ 有 activity，需结构化到「信号→订单→成交」链路
- 风控限额（单笔风险/单日亏损/最大持仓）—— ⚠️ 常量硬编码，需可配置 + 熔断

### 3.3 技术实现
- **挂载点**：扩展现有 `shell.overlay` 的浮层 → 新增会话内**独立视图**（`conversation.view` slot，`id: trading-workbench`），浮层保留为快速摘要入口。
- **图表实现**：**零依赖自绘**（`<canvas>` 或 SVG）优先 —— 客户端模块工厂直接 `require("react")`，无打包器保证，引入第三方图表库有风险。首期实现 K线/折线/柱状/热力图四类基础图元（各 ~100 行），后续若确认打包链路可换 lightweight-charts。
- **数据通道**：扩展 RPC 白名单，从 `{snapshot, switch-mode}` 增到 `{snapshot, switch-mode, series, bars, factor, backtest, orders}`；Host 侧新增 `WorkbenchStore` 读取 + 工具代理（复用 `quant`/`futu` 调用）。
- **存储**：`snapshot` 保持轻量（概览 + 最新 N 条）；序列数据（K线/权益曲线）单独 endpoint 按需拉取，避免每 3 秒传大数组。历史序列落 `~/.dsh/trading-series/`（按标的分文件，追加写）。
- **刷新策略**：概览 3 秒轮询；图表按需加载 + 手动刷新；交易时段内可 15~60 秒轮询 K 线。
- **主题**：沿用 `--dsw-alias-*` 令牌（现有 CSS 已建立），图表颜色取 `state-success/error`、`label-*`。

## 四、数据缺口与补齐方案（关键路径）

| 缺口 | 影响 | 方案 |
|---|---|---|
| **富途 MCP K线工具 internal error** | 无法直接取多周期 K 线 | ① 用会话内 dsh-mcp-client 复验（可能裸 HTTP 问题）；② 退回新浪日线；③ 自建 K 线缓存（快照轮询累积 + 日线源拼接） |
| 无推送订阅 | 只能轮询，秒级受限 | 轮询（分钟级够用）；若需秒级 → 评估 OpenD 推送（重量级） |
| 无因子计算层 | 无法做横截面选股 | 新增 Python 因子库（复用 akshare/新浪 + 富途财务），输出标准化因子矩阵 |
| 无 TCA | 无法评估执行质量 | 记录订单期望价 vs 成交价，计算滑点与实现差价 |
| 无事件对齐 | 事件风险靠人工 | 拉财报/分红/宏观日历，与持仓和信号做交集告警 |
| 风控常量硬编码 | 无法按账户调整 | 风控配置化（文件或 store），支持单笔风险/单日亏损熔断/最大持仓/行业上限 |

## 六、风险与边界

1. **合规**：工作台只展示与研究，不构成投资建议；实盘执行必须经 Harness 审批流（现有策略已强制）。
2. **数据延迟**：MCP 为拉取式，非交易所直连；分钟级可用，秒级/高频不适用，界面必须显示数据时间戳与新鲜度。
3. **回测偏差**：参数优化易过拟合 → 强制 walk-forward 与样本外；成本建模必须保留（现有佣金/印花税/滑点）。
4. **账户隔离**：序列与图表数据也必须按 `mode` 分区，避免 sim 数据污染 live 视图。
5. **性能**：大数组经 RPC 传输会拖慢面板 → 服务端聚合（降采样/OHLC 合并）后再传。

## 八、统一数据层（已实施）

三条路径**共用同一份实现**：`plugins/datasource`（`@bstester/dsh-datasource`）持有唯一的
富途 MCP 客户端、行情路由与回测核心。富途 MCP 优先（全市场、分钟/日线 + 盘口/财务/资讯），
A股长历史（>370 根）回退新浪源；资讯/情绪仍由 fin-data 独家负责。

| 路径 | 代码入口 | 数据来源 | 覆盖市场 |
|---|---|---|---|
| 研报（Harness 会话） | `mcp__futu__*` 工具 + `fin_news`/`fin_sentiment` | 富途 MCP + fin-data | 全市场 |
| 量化（引擎工具） | `engine.py` / `backtest.py` → `trading_datasource.market.load_bars` | 富途优先 → 新浪 | 全市场 |
| 工作台图表 | `bars.py` → `trading_datasource.market.load_bars` | 富途优先 → 新浪 | 全市场 |
| 量化侧情绪（可选） | `engine.py --sentiment` → `locate.run_script("fin-data", ...)` | fin-data（X/Reddit/AKShare） | 全市场 |

**为什么合并**：同一件事此前有多份实现——行情路由 2 份（`workbench/bars.py` 与
`engine/market_data.py`，91 行逐字相同）、富途 MCP 客户端 4 份、回测核心 2 份
（278 行仅差一行 import）。危害不是重复代码，而是**修一处漏一处**：富途 K 线
`internal error` 排查时根因是参数名写错，只有一份实现所以改一次就好；
同样的问题若发生在 `fetch_futu` 上要改三处，漏掉的那处会安静地继续坏着。

`market_data.py`、`futu_client.py`、`workbench/backtest.py` 已删除，
`backtest.py` 与 `bars.py` 降为薄入口，净删约 700 行。

**安装后如何被找到**：安装器把该包的 `python/` 解到 `$DSH_HOME/trading-python/datasource/`，
并向交易 venv 写 `dsh-trading-python.pth`，因此插件脚本直接 `import trading_datasource` 即可，
无需 `PYTHONPATH`。该目录是安装时生成的副本，仓库版本是唯一事实来源，重装即刷新。
包刻意**不 eager 导入**子模块——`import trading_datasource` 不拉起 `urllib`/`ssl`，
纯本地路径不为网络栈付代价，也不会在禁网沙箱里失败。

**量化侧的情绪是可选并列输入**：`quant_signal(include_sentiment=true)` 返回 `sentiment`
字段，但**不参与信号计算、不改风控参数**。信号必须能由历史数据复现，否则回测结论无法验证；
测试中有性质断言锁住「带不带情绪，`signal`/`price`/`atr` 必须完全一致」。

## 九、数据渠道优先级（用户约定）

1. **富途 MCP 优先**：凡富途能提供的（K线/快照/盘口/分时/逐笔/公司资料/估值/财报/资金流/
   股东/分红/新闻/社区/板块/经济日历）一律先走富途——快、权威、覆盖全市场（A股/港股/美股）；
2. **备用通道**：AKShare（A股长历史日线、披露预约、千股千评）、Yahoo RSS（港美股资讯）、
   富途公开快讯接口（免鉴权）；
3. **X（必取渠道）**：社交情绪必查，一次登录后持久复用；
4. **Reddit**：与 X 共用专属浏览器配置，同样登录一次。
   注意：`old.reddit.com` 要求独立登录，脚本已改用 `www.reddit.com` 搜索页（登录态共享）。

登录一次即可（登录态持久保存）：
```bash
python plugins/fin-data/python/x_search.py --login        # X
python plugins/fin-data/python/reddit_search.py --login   # Reddit
```
工作台「审计」页的「数据源与授权状态」会显示各渠道登录态（基于会话 cookie 名称，不解密内容）。

## 十、工作台交互

- **研报详情**：研报列表点击标题 → 抽屉内全幅详情页（正文 + 来源），并可「在新标签打开」；
- **列表分页**：研报、信号预览、成交记录、券商响应、事件、审计时间线统一分页
  （页码 + 上/下页 + 总数），避免超长列表。
- **不显示行情图表**：行情页为「标的卡片」（名称/最新价/涨跌/开高低/成交量额 + 数据来源与日期），
  点击**「在富途查看K线 ↗」**跳转富途对应标的页面；
- **无示例数据**：不内置任何默认标的或标的池，未查询时留空；持仓为空则权益/相关性/台账均为空。


### 执行页 = 交易概要，不是工具调用清单

「执行」页原先第二张卡把每条券商响应用 `JSON.stringify` 原样铺开，同一个工具调 7 次
就有 7 行重复，看起来像发生了很多笔交易。现在改为**交易概要**：

- **订单明细**：按 `order_id` 去重（保留最后一次观测），显示标的、方向、委托量/价、
  成交量/均价、成交金额与成交情况；
- **动作**：下单/改单/撤单及其结果，失败带原始原因；
- **只读查询**：只计数并列出工具名×次数，不逐条铺开；
- **原始响应**：折叠保留，作为审计核对材料。

归纳原则是**只归纳、不推测**：金额用「已成交数量 × 成交均价」（两个数都来自券商原文）；
方向取 schema 明文；成交情况由数量推导；`status` 码原样附上而不猜枚举含义；
「已撤单」只依据我们记录到的、券商返回 success 的撤单动作。

### 缓存策略（不追求实时）

面板不需要实时数据，因此**两层缓存**避免频繁取数：

| 层 | TTL | 说明 |
|---|---|---|
| 客户端内存 | 与 Host 同量级 | 切页签/重开面板直接复用，不再发请求 |
| Host RPC | instrument/series/risk 5 分钟；equity/positions/sources 2 分钟；factors/ic/correlation 10 分钟；sensitivity/events 30 分钟；trades/audit 1 分钟 | 客户端重新请求也不会重跑 python 子进程与富途调用 |

快照兜底轮询从 3 秒放宽到 **60 秒**；「刷新」按钮清客户端缓存并让随后 5 秒的请求
穿透 Host 缓存。切换模拟/实盘会清缓存。界面明确提示"数据按 TTL 本地缓存，
不追求实时行情；实时价格请用富途行情工具查询"。

### 接口自检（解决"404 一片"）

Host 在 snapshot 里声明实际提供的接口；客户端据此跳过缺失接口并给出可读原因
（"当前 dsh web 进程早于插件更新，重启后可用"），而不是抛一句 `HTTP 404`。
对不声明清单的旧 Host，客户端从 404 反推并记住，同样停止重试。

## 十一、社交渠道的浏览器与 API 策略

**资源策略（复用 + 及时关闭）**
- 浏览器只在需要时启动一次；X 与 Reddit **复用同一个专属浏览器与同一个标记标签**
  （标签 URL 带 `dsh_scratch=1`，脚本只操作自己的标签，绝不关闭用户自己的标签）；
- 任务结束后立即关闭标签；浏览器仅在「由脚本启动」时才被关闭
  （以 pid 文件判定，**不再按端口误杀**——早期实现会杀掉用户自己的浏览器并导致反复冷启动）；
- `fin_sentiment` 作为父进程设置 `SOCIAL_BROWSER_PERSIST=1`，让 X 与 Reddit 共享一次浏览器启动，
  两个渠道跑完后由父进程统一关闭；
- 应急清理：`python .../x_search.py --force-clean`（按端口强制清理，慎用）。

**API vs 网页（实测结论）**

| 渠道 | 路径 | 结论 |
|---|---|---|
| **Reddit** | **API（同源 `/search.json`，纯 HTTP + 缓存 cookie）** | ✅ 采用。结构化返回（标题/子版/分数/评论数/时间）。cookie 缓存到 `~/.dsh/reddit-cookies.json`（3 天），热路径**完全不启动浏览器**，约 3s（此前每次开浏览器约 37s） |
| **X** | **API（GraphQL `SearchTimeline` + 社区 `x-client-transaction-id` 实现）** | ✅ 已打通。DOM 抓取保留为降级路径 |

X 的 GraphQL 搜索此前返回 HTTP 404，原因不是鉴权缺失，而是缺少反爬头
`x-client-transaction-id`——该值由客户端混淆算法现场生成。**不自行逆向**，直接采用社区实现
[`XClientTransaction`](https://github.com/iSarabjitDhiman/XClientTransaction)（PyPI `XClientTransaction`，导入名
`x_client_transaction`），实现见 `plugins/fin-data/python/x_api.py`：

1. **cookie 获取**：通过 CDP 从已登录的专属浏览器取 `auth_token`/`ct0`（浏览器已完成解密，
   我们不接触密文），缓存到 `~/.dsh/x-cookies.json`，有效期 3 天。取 cookie 的函数对域名与必需
   cookie 名参数化（`extract_cookies_via_browser(domains=..., required=...)`），Reddit 复用同一套机制；
2. **素材与 queryId**：抓 `x.com/home` → 从 `client-web/main.*.js` 里提取 `SearchTimeline` 的
   `queryId`（**注意：queryId 不在首页 HTML 中**），连同 ondemand 脚本缓存到
   `~/.dsh/x-client-material.json`，有效期 30 分钟；
3. **请求**：`ClientTransaction.generate_transaction_id(method="GET", path=...)` 生成反爬头，
   以固定 Bearer 直连 GraphQL，解析 `SearchTimeline` 时间线。

实测（多次取中位）：X 冷启动约 8.5s（含开浏览器取 cookie）、热启动约 3.8s，单次约 20 条推文；
Reddit 热启动约 3.7s；两渠道合并约 8s。对照组为 X DOM 抓取约 40-50s、Reddit 每次开浏览器约 37s。
cookie 缓存命中后两个渠道都**不再启动浏览器**。

脚本输出中的 `path` 字段标明本次实际路径：`api/graphql`（X）、`api/json`（Reddit）、`web/dom`（降级）。
`fin_sentiment` 的 `sources_status` 会显示为 `ok:api/graphql` 形式，便于确认是否走了 API。

> 脆弱性提示：queryId 与混淆算法随 X 前端发版变更。x_api 任一环节失败即返回 `None`，
> 由 `x_search.py` 自动降级到 DOM 抓取，因此渠道不会因上游变更而整体不可用。
