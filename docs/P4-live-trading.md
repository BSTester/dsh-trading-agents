# 实盘边界与准入清单

> **WP4 状态标注（WP5 修订）：** 本文新增的 daemon 执行链路演练、kill switch 演练、
> 「执行已冻结计划」入口等描述按 WP4 计划规格撰写，**以 WP4 合并后实测为准**。

**当前是 Harness 原生投研与量化工作台框架，不是已完成验收的自动实盘系统。**
工作台不提供逐单下单/撤单表单；唯一执行入口是「执行已冻结计划」——受约束 RPC
（live 需口令复核），逐笔实盘指令、订单摘要确认、提交/改单/撤单仍在 Harness 中完成。

## 模式切换不是订单授权

初始模式缺失时为 sim。模式文件持久化，**重启不会自动回到 sim**。
用户在工作台输入「确认实盘」后才能切 live；在途账户调用期间拒绝切换。
`quant_switch` 与 `scripts/trade_mode.py sim` 只能切回模拟模式，不能替用户开启实盘。

切 live 后，`account_*` 与 `trading_*` 属于真实账户，`sim_trade_*` 被拒绝；
sim 时相反。完整安装的引擎才提供这层工具守卫；仅克隆 preset 的基础 skill
不应被当作具有相同的执行保护。

## 实盘前必须满足

1. 本机完整安装、重启后的新会话可用；工作台数据来源与模式正确；
2. 富途授权及实际账户权限明确，日常只读，需要写权限时由用户决定授权 `--write`；
3. 在富途模拟账户完成下单、拒单、部分成交、查询、改单、撤单、断线恢复与对账；
4. 明确仓位上限、真实止损执行、组合敞口、日内亏损熔断、紧急停机与告警；
5. 策略经过包含成本的样本外/滚动评估；两到四周模拟盈利不是充分证据；
6. 操作者理解工具响应、订单受理与实际成交的差异，并能核对券商记录；
7. daemon 执行链路演练通过（崩溃重启、指令去重、unknown 在途兜底，见 RUNBOOK 场景 1/2）；
8. kill switch 演练通过（`scripts/drills.sh` 风控联动 + 熔断/恢复处置，见 RUNBOOK 场景 3）；
9. 对账零差异连续 3 个交易日（sim）；
10. 独立 Web + MCP 入口审批回归通过（规格 §5.3 人工清单 5 步：25 工具出现 / MCP
    拒绝切 live / Web 口令切 live / live 写操作原生审批卡 / 计划执行窄门 + kill 联动），
    证据留档于 `docs/superpowers/plans/2026-09-15-wp6-standalone-service.md` 末节。

其中实时成交推送尚未实现；自动对账、调度熔断与告警由 WP3–WP4 交付，
以 WP4 合并后实测验收为准——不能用“框架已就绪，只差用户确认”代替这些条件。

## 模拟账户联调记录与调用约束

2026-09-12 已通过 Harness 原生工具链实测港股模拟账户：查询资金/持仓、限价下单、
查询受理状态、改单、撤单和资金释放。两笔测试单均撤销，成交量为零，原持仓未变。
这不是实盘或成交链路验收；完整结果见 [HANDOVER.md](HANDOVER.md)。

- 先查 `sim_trade_account_list`，使用实际返回的账户 ID 和 `market_id`；
  港股持仓查询显式带 `market=1`，省略会在本次环境返回业务错误。
- 改单前先查询该订单，再同时提交新价格和新数量；仅改价格时数量使用查询到的
  当前数量，不猜测数量。本次仅传 `new_price` 失败，补齐 `new_qty` 后成功。
- MCP `isError=false` 只说明工具调用外层未报错；继续检查响应 JSON 的 `ret_code`，
  非零仍是业务失败。提交成功后必须查询订单状态与累计成交量，不能据此宣称成交。
- 下单/改单超时不重放：先重连查询已有订单；撤单后再核对取消状态和冻结资金。
- 本次账户与行情同报 `-32603`，使用现有 refresh 凭据续期后恢复。
  遇到类似问题应区分连接失败、授权问题和业务错误；续期不会自动增加写权限。

## 每笔操作在 Harness 中确认

先查询当前模式、真实可用资金和持仓；不得使用本地量化台账冒充账户状态。
下单前展示完整摘要：

```text
账户：live（真实账户，标识应与用户选择一致）
标的、市场、币种：
方向、数量、订单类型、限价：
有效期：
预计金额与费用：
最坏情况与仓位影响：
请确认这笔具体订单。
```

对话确认后，真实写工具还会在工作台弹出**业务确认**（阻塞等用户点确认，超时按拒绝）；富途返回
`need_order_confirm` 时按券商要求再次确认。拒绝审批即停止，不通过 shell、
直接 HTTP 或其他工具绕过。超时或未知状态先查询订单，不能直接重试下单。

## 数据与恢复

工作台显示最近的 Harness 账户工具响应，并标注时间；没有响应显示未知，
不等于余额为零。`SUBMITTED` 不代表成交。量化预览/本地模拟台账不会触发券商订单，
`--apply` 也不得写入实盘假成交。

异常退出可能留下 `trading-workbench.lock` 或 `trading-call-*.active`。
先核对券商订单并确认相关进程已结束，再检查并清理具体残留文件；
不要自动清除未知在途调用的租约。收工后在工作台显式切回 sim。

## 保护范围

插件控制的是 Harness MCP 工具路径，不是操作系统沙箱。宿主所有者拥有文件、
shell 和凭据权限，仍可绕过插件；只读授权与操作权限隔离仍然必要。
本项目输出是研究资料，不构成投资建议，也不保证收益或限制实际跳空损失。
